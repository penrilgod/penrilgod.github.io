## 1. 서론: 아직도 AWS Dev 계정에서 테스트하시나요?

현대 백엔드 아키텍처에서 AWS S3, DynamoDB, SQS 같은 클라우드 관리형 서비스는 필수적입니다. 하지만 이러한 클라우드 종속성이 있는 코드를 테스트할 때, 많은 개발팀이 여전히 다음과 같은 페인 포인트(Pain Points)를 겪고 있습니다.

1. **비용 폭탄 (FinOps의 적):** 테스트용으로 무심코 생성한 RDS 인스턴스, S3 버킷, 혹은 테스트 루프 실수로 인한 API 호출 폭증으로 수백 달러의 청구서가 날아옵니다.
2. **테스트 환경 오염 (State Pollution):** 여러 개발자 혹은 CI/CD 러너가 공유 AWS 개발(Dev) 계정에서 동시에 테스트를 수행하다 보면, 서로의 데이터가 뒤엉켜 테스트 신뢰성이 깨집니다.
3. **네트워크 레이턴시:** 해외 AWS 리전과 매번 API 통신을 주고받아야 하므로 전체 빌드 및 배포 파이프라인 속도가 급격히 저하됩니다.

이러한 문제를 해결하기 위해 과거에는 Mocking(가짜 객체 사용) 기법을 자주 사용했으나, Mocking은 실제 AWS API의 세부 동작 방식(에러 코드, 권한 체계, 데이터 포맷)을 완벽히 흉내 내지 못해 **"로컬 테스트는 통과했는데 배포하니 에러가 나는"** 참사를 막기 어렵습니다.

이 글에서는 20년 차 시니어 엔지니어의 관점에서, **LocalStack**과 **Testcontainers**를 결합하여 개발자 개인 PC와 GitHub Actions 내부에서 완벽하게 격리된 '자급자족형' 로컬 AWS 테스트 샌드박스를 구축하는 방법을 가이드합니다.

## 2. 개념 정리: Mocking의 한계를 넘는 LocalStack과 Testcontainers의 시너지

본론으로 들어가기 전, 우리가 도입하려는 기술의 핵심 개념을 명확히 정리해 보겠습니다.

```
┌────────────────────────────────────────────────────────┐
│                      pytest Runner                     │
└───────────────────────────┬────────────────────────────┘
                            │ (1) Container Lifecycle Control
                            ▼
┌────────────────────────────────────────────────────────┐
│                 Testcontainers (Python)                │
└───────────────────────────┬────────────────────────────┘
                            │ (2) Runs & Manages
                            ▼
┌────────────────────────────────────────────────────────┐
│                  LocalStack (Docker)                   │
│   ┌───────────────────────────┬────────────────────┐   │
│   │ S3 Bucket (user-profiles) │ DynamoDB Table     │   │
│   └───────────────────────────┴────────────────────┘   │
└────────────────────────────────────────────────────────┘
```

* **LocalStack 3.x:** AWS의 핵심 서비스(S3, DynamoDB, SQS, Lambda 등)를 로컬 Docker 컨테이너 하나로 완벽하게 에뮬레이트하는 도구입니다. 실제 AWS와 99% 동일한 REST API 엔드포인트를 제공하여, 개발자는 `boto3`의 엔드포인트 URL만 LocalStack으로 돌려주면 실제 AWS 환경처럼 동작합니다.
* **Testcontainers:** 테스트 코드 안에서 필요한 Docker 컨테이너(Database, LocalStack 등)를 자동으로 실행하고 테스트가 종료되면 흔적 없이 청소(Clean-up)해 주는 강력한 코드 기반 인프라 관리 라이브러리입니다.

이 둘이 결합하면 **"테스트 실행 버튼 클릭 ➔ 로컬 Docker에 AWS 가상 인프라 가동 ➔ 가상 S3/DynamoDB 인프라 세팅 ➔ API 테스트 수행 ➔ 컨테이너 소멸 및 리소스 반환"**의 파이프라인이 코드 몇 줄로 완전히 자동화됩니다.

## 3. 실전 가이드: FastAPI + Boto3 + pytest 기반의 통합 테스트 구축

실제 비즈니스 시나리오를 바탕으로 구현해 보겠습니다.

> **구현 시나리오**
> 1. 사용자가 프로필 이미지를 업로드하면, S3에 업로드하고 메타데이터(파일명, 용량, 업로드 시각)를 DynamoDB 테이블에 기록하는 FastAPI 기반 백엔드 애플리케이션.
> 2. `pytest`를 실행할 때 `testcontainers-localstack` 라이브러리를 사용해 이 인프라 전체를 로컬에서 테스트합니다.

### 3.1. 필요한 패키지 설치

먼저 테스트에 필요한 Python 라이브러리를 설치합니다. Docker가 백그라운드에 구동 중이어야 합니다.

```bash
pip install fastapi boto3 pytest pytest-asyncio httpx testcontainers[localstack]
```

### 3.2. 통합 테스트 및 애플리케이션 코드 구현

이 코드는 실제 구동 가능한 예시입니다. `conftest.py` 설정과 실제 테스트 케이스를 하나로 묶어 직관적으로 표현했습니다. 실제 프로젝트에서는 파일별로 분리하여 관리하는 것을 권장합니다.

```python
import os
import pytest
import boto3
from fastapi import FastAPI, UploadFile, File, Form
from fastapi.testclient import TestClient
from testcontainers.localstack import LocalStackContainer

# ---------------------------------------------------------
# 1. 테스트 대상 FastAPI 비즈니스 로직 정의
# ---------------------------------------------------------
app = FastAPI()

# 실제 서비스 코드에서는 환경 변수에 따라 AWS endpoint_url을 동적으로 설정합니다.
def get_aws_client(service_name: str):
    endpoint_url = os.getenv("AWS_ENDPOINT_URL")
    if endpoint_url:
        return boto3.client(
            service_name,
            endpoint_url=endpoint_url,
            aws_access_key_id="test",
            aws_secret_access_key="test",
            region_name="us-east-1"
        )
    return boto3.client(service_name)

@app.post("/profile/upload")
async def upload_profile_image(
    user_id: str = Form(...), 
    file: UploadFile = File(...)
):
    s3_client = get_aws_client("s3")
    dynamodb = get_aws_client("dynamodb")
    
    bucket_name = "user-profiles"
    table_name = "user-metadata"
    
    # 1. S3 업로드
    file_content = await file.read()
    s3_client.put_object(
        Bucket=bucket_name,
        Key=f"profiles/{user_id}/{file.filename}",
        Body=file_content,
        ContentType=file.content_type
    )
    
    # 2. DynamoDB 메타데이터 적재
    dynamodb.put_item(
        TableName=table_name,
        Item={
            "user_id": {"S": user_id},
            "file_name": {"S": file.filename},
            "file_size": {"N": str(len(file_content))}
        }
    )
    
    return {"status": "success", "user_id": user_id, "file_name": file.filename}

# ---------------------------------------------------------
# 2. Pytest + Testcontainers 설정 (Fixture)
# ---------------------------------------------------------
@pytest.fixture(scope="session", autouse=True)
def localstack_sandbox():
    """
    Testcontainers를 활용해 LocalStack 컨테이너를 가동합니다.
    테스트가 실행되면 컨테이너를 띄우고, 테스트가 세션 단위로 종료되면 자동 리소스 회수합니다.
    """
    # LocalStack 3.x 버전을 활용하여 격리 환경 생성
    with LocalStackContainer(image="localstack/localstack:3.4.0") as localstack:
        # FastAPI 서버가 가상의 AWS 엔드포인트를 바라보도록 환경변수 주입
        endpoint_url = localstack.get_url()
        os.environ["AWS_ENDPOINT_URL"] = endpoint_url
        os.environ["AWS_DEFAULT_REGION"] = "us-east-1"
        
        # 3. 로컬 클라우드 인프라 초기화 (S3 버킷 및 DynamoDB 테이블 사전 생성)
        setup_local_infrastructure(endpoint_url)
        
        yield localstack

def setup_local_infrastructure(endpoint_url: str):
    """테스트 구동 전 인프라 테이블과 버킷을 미리 생성하는 헬퍼 함수"""
    s3 = boto3.client("s3", endpoint_url=endpoint_url, aws_access_key_id="test", aws_secret_access_key="test", region_name="us-east-1")
    dynamodb = boto3.client("dynamodb", endpoint_url=endpoint_url, aws_access_key_id="test", aws_secret_access_key="test", region_name="us-east-1")
    
    # 가상 S3 버킷 생성
    s3.create_bucket(Bucket="user-profiles")
    
    # 가상 DynamoDB 테이블 생성
    dynamodb.create_table(
        TableName="user-metadata",
        KeySchema=[{"AttributeName": "user_id", "KeyType": "HASH"}],
        AttributeDefinitions=[{"AttributeName": "user_id", "AttributeType": "S"}],
        BillingMode="PAY_PER_REQUEST"
    )

# ---------------------------------------------------------
# 3. 실제 시나리오 통합 테스트 작성
# ---------------------------------------------------------
def test_profile_upload_flow():
    # FastAPI TestClient 초기화
    client = TestClient(app)
    
    # 테스트용 파일 데이터 구성
    user_id = "user_2026_0825"
    file_payload = {
        "file": ("avatar.png", b"fake_png_binary_data_here", "image/png")
    }
    data_payload = {
        "user_id": user_id
    }
    
    # API 요청 전송
    response = client.post(
        "/profile/upload",
        files=file_payload,
        data=data_payload
    )
    
    # 1단계: API 응답값 검증
    assert response.status_code == 200
    assert response.json()["status"] == "success"
    
    # 2단계: LocalStack S3 데이터 실무 검증 (Mock이 아닌 실제 바이너리 조회)
    endpoint_url = os.getenv("AWS_ENDPOINT_URL")
    s3_client = boto3.client("s3", endpoint_url=endpoint_url, aws_access_key_id="test", aws_secret_access_key="test", region_name="us-east-1")
    
    obj = s3_client.get_object(Bucket="user-profiles", Key=f"profiles/{user_id}/avatar.png")
    assert obj["Body"].read() == b"fake_png_binary_data_here"
    
    # 3단계: LocalStack DynamoDB 메타데이터 검증
    dynamodb = boto3.client("dynamodb", endpoint_url=endpoint_url, aws_access_key_id="test", aws_secret_access_key="test", region_name="us-east-1")
    res = dynamodb.get_item(TableName="user-metadata", Key={"user_id": {"S": user_id}})
    
    assert "Item" in res
    assert res["Item"]["file_name"]["S"] == "avatar.png"
    assert res["Item"]["file_size"]["N"] == str(len(b"fake_png_binary_data_here"))
```

### 3.3. 테스트 작동 흐름 분석
위 테스트 코드를 `pytest`로 실행하면 다음과 같은 작업이 백그라운드에서 단숨에 진행됩니다.
1. `LocalStackContainer`가 구동하며 호스트 PC의 사용 가능한 포트에 도커를 바인딩합니다.
2. `get_url()`을 통해 동적으로 바인딩된 포트 정보가 들어간 엔드포인트 URL(`http://localhost:54321` 등)을 가져옵니다.
3. `setup_local_infrastructure`가 실행되어 `boto3`를 사용해 가상 AWS 인프라에 `user-profiles` 버킷과 `user-metadata` 테이블을 생성합니다.
4. FastAPI에 요청을 보내면, 내부 비즈니스 코드가 해당 LocalStack 엔드포인트를 찾아 파일 업로드와 메타데이터 저장을 완벽히 수행합니다.
5. 테스트 세션이 종료되면 Testcontainers가 LocalStack 컨테이너를 정지하고 삭제합니다.

## 4. CI/CD 연동: GitHub Actions에서 외부 자격증명 없이 30초 만에 완주하기

로컬에서 완벽하게 동작하는 이 통합 테스트 코드는 **GitHub Actions** 파이프라인 안에서도 아무런 추가 설정(AWS Credential 주입 등) 없이 그대로 작동합니다. GitHub Actions 러너에는 기본적으로 Docker가 내장되어 있기 때문입니다.

다음은 해당 흐름을 지원하는 아주 심플하고 깔끔한 `.github/workflows/test.yml` 구성 예시입니다.

```yaml
name: Run Integration Tests

on: [push, pull_request]

jobs:
  integration-test:
    runs-on: ubuntu-latest

    steps:
    - name: Checkout Code
      uses: actions/checkout@v4

    - name: Set up Python
      uses: actions/setup-python@v5
      with:
        python-version: '3.11'

    - name: Install Dependencies
      run: |
        python -m pip install --upgrade pip
        pip install fastapi boto3 pytest pytest-asyncio httpx testcontainers[localstack]

    - name: Run Pytest with LocalStack Container
      run: |
        pytest
```

**💡 장점:** 복잡한 AWS IAM Role(OIDC) 설정이나, AWS Access Key를 GitHub Secret에 저장해 두는 보안 리스크 없이도 완벽히 격리된 독립형 빌드가 가능해집니다.

## 5. 💡 실무 적용 팁: 프로덕션 레벨에서의 최적화 전략

수년 간 실제 엔터프라이즈 환경에서 이 아키텍처를 도입하며 정립한 최적화 전략 노하우를 공유합니다.

* **컨테이너 재사용 (Singleton Pattern) 도입:**
  각 테스트 파일(Module) 마다 컨테이너를 새로 띄우면 테스트 구동 속도가 극도로 느려집니다. 위의 예시처럼 `scope="session"`으로 설정하여 전체 테스트 세션 동안 단 **한 번**만 컨테이너가 뜨도록 최적화해야 합니다.
* **LocalStack 도커 이미지 캐싱:**
  CI/CD 파이프라인에서 매번 `localstack/localstack` 이미지를 다운로드(Pull)하면 빌드 시간이 늘어납니다. GitHub Actions의 캐시 액션(`actions/cache`)을 사용하거나 빌드 러너 내부에 로컬 베이스 이미지를 프레이밍해 두면 빌드 시간을 최대 40% 단축할 수 있습니다.
* **Pro 기능과 Community 기능 구분:**
  무료 버전(Community Edition)의 LocalStack도 S3, DynamoDB, SQS, SNS, IAM 등을 대부분 지원합니다. 하지만 Cognito, RDS, EKS 등 고도화된 클라우드 서비스는 유료 플랜(Pro)에서 지원하므로, 본인의 아키텍처 범위에 맞추어 검토가 필요합니다.

## 6. 결론: 로컬 퍼스트(Local-first) 개발이 주는 생산성의 혁신

클라우드 네이티브 개발 환경이 고도화될수록 인프라에 대한 의존성은 커지고, 이는 배포 전 검증 과정에서의 비용 증가와 생산성 저하라는 역설을 낳았습니다.

오늘 소개한 **LocalStack과 Testcontainers의 조합**은 단순히 "비용을 아끼는 기법"을 넘어섭니다. 개발자가 네트워크 환경에 구애받지 않고 오프라인(비행기 안, 카페 등)에서도 프로덕션과 거의 완벽하게 일치하는 클라우드 환경을 손안에 쥐고 마음껏 리팩토링하고 테스트할 수 있는 **'로컬 퍼스트(Local-first) 개발 문화'**의 핵심 동력입니다.

더 이상 불필요한 AWS 자격 증명 오류나 청구서 폭탄에 시달리지 마세요. 지금 바로 여러분의 프로젝트에 `testcontainers`를 도입하여 백엔드 생산성의 극적인 향상을 직접 경험해 보시길 권장합니다.
