    1. 들어가는 글: 왜 로컬 클라우드 모킹 통합 테스트인가?#

    현대 백엔드 개발에서 AWS의 S3, SQS, DynamoDB와 같은 관리형 서비스는 아키텍처의 핵심 뼈대입니다. 그러나 이 편리한 서비스들은 테스트 단계에서 고질적인 세 가지 페인 포인트(Pain Point)를 유발하곤 합니다.

    1. 비용 및 관리 오버헤드: 테스트 전용 AWS 계정을 파고 지우는 과정에서 리소스 누수로 인한 예상치 못한 요금 폭탄이 발생합니다.
    2. 테스트 격리 실패: 여러 개발자나 CI/CD 파이프라인이 하나의 AWS 샌드박스 계정을 공유하면서 데이터가 뒤엉키고 깨지는 현상이 빈번합니다.
    3. 네트워크 의존성: 불안정한 오프라인 환경이나 제한된 사내망에서는 원격지 클라우드 리소스에 접근할 수 없어 생산성이 저하됩니다.

    20년 동안 백엔드 아키텍처를 설계하면서 이러한 문제를 해결하기 위해 모의(Mocking) 라이브러리를 많이 사용해 보았지만, 모킹은 결국 실제 API의 동작을 완벽히 모사하지 못해 배포 직후 런타임 에러를 뿜어내기 일쑤였습니다.

    이에 대한 우아한 해답이 바로 LocalStack과 Testcontainers의 조합입니다. 이번 글에서는 이 두 도구를 활용하여 클라우드 비용을 단 1원도 쓰지 않고, 격리성이 완벽히 보장된 고성능 로컬 통합 테스트 파이프라인을 구축하는 실전 가이드를 소개합니다.

    2. 핵심 기술 스택 및 개념 이해#

    시작하기에 앞서, 우리가 사용할 도구들의 핵심 메커니즘을 짚고 넘어가겠습니다.

    ┌────────────────────────────────────────────────────────┐
│                     Test Run (pytest)                  │
│                                                        │
│  1. Spin up Container   ───►  [Testcontainers]         │
│  2. Run LocalStack      ───►  [Docker Engine]          │
│  3. Execute AWS SDK     ───►  boto3 (Port: 4566)       │
│  4. Terminate & Clean   ───►  Ryuk Container Auto-Kill │
└────────────────────────────────────────────────────────┘
    • LocalStack: PC 또는 CI 서버에서 실제 AWS 클라우드 서비스(S3, SQS, Lambda, DynamoDB 등)와 완전히 동일하게 응답하는 Mocking API 서버를 제공하는 가벼운 프레임워크입니다.
    • Testcontainers: Docker 컨테이너를 애플리케이션 테스트 코드 레벨에서 프로그래밍 방식으로 제어할 수 있게 돕는 라이브러리입니다. 테스트 시작 시 필요한 인프라를 자동으로 띄우고, 테스트가 끝나면 소멸(Clean-up)시켜 줍니다.
    • AWS SDK (boto3 in Python): 로컬 호스트와 매핑된 포트(http://localhost:<dynamic_port>)로 엔드포인트를 우회하여 실제 AWS 서비스 대신 LocalStack과 원활하게 통신하게 만듭니다.

    3. 실무 시나리오 기반 통합 테스트 단계별 구현#

    이번 예제에서 다룰 비즈니스 유스케이스는 다음과 같습니다.

    “사용자가 업로드한 원본 파일을 S3에 저장하고, 메타데이터를 DynamoDB에 남긴 뒤, 다른 마이크로서비스가 전처리할 수 있도록 SQS 큐로 이벤트를 발행한다.”

    3.1. 개발 환경 설정 및 의존성 설치#

    통합 테스트 코드를 빌드하고 구동하려면 로컬에 Docker Daemon이 실행 중이어야 합니다. 이후 필요한 파이썬 패키지를 설치합니다.

    pip install pytest boto3 testcontainers[localstack]

    3.2. 실전 파이썬 코드 구현#

    아래는 테스트 시작 전 LocalStack 컨테이너를 띄우고, S3/DynamoDB/SQS 리소스를 생성한 뒤, 비즈니스 로직을 호출하고 검증까지 끝 마친 후 자동으로 리소스를 삭제하는 전체 통합 테스트 코드입니다.

    import os
import time
import pytest
import boto3
from botocore.exceptions import ClientError
from testcontainers.localstack import LocalStackContainer

# ==========================================
# [비즈니스 로직 영역] 실제 애플리케이션 코드 예시
# ==========================================
class ImageProcessorService:
    """S3 업로드 -> DB 기록 -> SQS 메시지 발행을 담당하는 서비스 클래스"""
    def __init__(self, s3_client, db_client, sqs_client):
        self.s3 = s3_client
        self.db = db_client
        self.sqs = sqs_client

    def process_image_upload(self, bucket_name, table_name, queue_url, file_name, file_content):
        # 1. S3 버킷에 원본 파일 저장
        self.s3.put_object(Bucket=bucket_name, Key=file_name, Body=file_content)
        
        # 2. DynamoDB에 메타데이터 생성
        self.db.put_item(
            TableName=table_name,
            Item={
                'image_id': {'S': file_name},
                'status': {'S': 'UPLOADED'},
                'timestamp': {'N': str(int(time.time()))}
            }
        )
        
        # 3. SQS 큐에 완료 이벤트 발행
        message_body = f'{{"event": "IMAGE_UPLOADED", "file_name": "{file_name}"}}'
        self.sqs.send_message(QueueUrl=queue_url, MessageBody=message_body)
        return True


# ==========================================
# [통합 테스트 영역] Testcontainers & Pytest
# ==========================================
@pytest.fixture(scope="module")
def localstack_env():
    """Testcontainers를 활용해 LocalStack Docker 컨테이너를 구동합니다."""
    # S3, DynamoDB, SQS 서비스를 활성화한 LocalStack 컨테이너 기동
    with LocalStackContainer(image="localstack/localstack:latest") as localstack:
        # 동적으로 할당된 로컬 호스트 및 포트 정보 가져오기
        endpoint_url = localstack.get_url()
        
        # boto3 클라이언트가 로컬스택 엔드포인트를 바라보도록 클라이언트 초기화
        s3 = boto3.client("s3", endpoint_url=endpoint_url, region_name="us-east-1",
                          aws_access_key_id="mock_key", aws_secret_access_key="mock_secret")
        db = boto3.client("dynamodb", endpoint_url=endpoint_url, region_name="us-east-1",
                          aws_access_key_id="mock_key", aws_secret_access_key="mock_secret")
        sqs = boto3.client("sqs", endpoint_url=endpoint_url, region_name="us-east-1",
                           aws_access_key_id="mock_key", aws_secret_access_key="mock_secret")
        
        yield {
            "s3": s3,
            "db": db,
            "sqs": sqs,
            "endpoint_url": endpoint_url
        }


def test_image_processing_pipeline(localstack_env):
    # Given: 테스트에 필요한 클라이언트 및 리소스 이름 설정
    s3_client = localstack_env["s3"]
    db_client = localstack_env["db"]
    sqs_client = localstack_env["sqs"]
    
    bucket_name = "test-image-bucket"
    table_name = "test-image-meta"
    queue_name = "test-image-queue"
    
    # [인프라 초기 세팅] LocalStack 내부 인프라 리소스 동적 생성
    # 1. S3 버킷 생성
    s3_client.create_bucket(Bucket=bucket_name)
    
    # 2. DynamoDB 테이블 생성
    db_client.create_table(
        TableName=table_name,
        KeySchema=[{'AttributeName': 'image_id', 'KeyType': 'HASH'}],
        AttributeDefinitions=[{'AttributeName': 'image_id', 'AttributeType': 'S'}],
        BillingMode='PAY_PER_REQUEST'
    )
    
    # 3. SQS 큐 생성 및 URL 조회
    queue_res = sqs_client.create_queue(QueueName=queue_name)
    queue_url = queue_res['QueueUrl']
    
    # 4. 테스트 타겟 서비스 초기화
    service = ImageProcessorService(s3_client, db_client, sqs_client)
    
    test_file_name = "avatar_john_doe.png"
    test_content = b"fake_png_binary_data"

    # When: 실제 비즈니스 프로세스 파이프라인 수행
    success = service.process_image_upload(
        bucket_name, table_name, queue_url, test_file_name, test_content
    )
    
    # Then: 검증(Assertion) 수행
    assert success is True
    
    # 검증 1. S3에 파일이 올바르게 적재되었는가?
    s3_obj = s3_client.get_object(Bucket=bucket_name, Key=test_file_name)
    assert s3_obj['Body'].read() == test_content
    
    # 검증 2. DynamoDB에 메타데이터가 정상 기록되었는가?
    db_res = db_client.get_item(TableName=table_name, Key={'image_id': {'S': test_file_name}})
    assert 'Item' in db_res
    assert db_res['Item']['status']['S'] == 'UPLOADED'
    
    # 검증 3. SQS에 정상적으로 알림 이벤트 메시지가 인입되었는가?
    sqs_res = sqs_client.receive_message(QueueUrl=queue_url, MaxNumberOfMessages=1)
    assert 'Messages' in sqs_res
    assert len(sqs_res['Messages']) == 1
    
    msg_body = sqs_res['Messages'][0]['Body']
    assert "IMAGE_UPLOADED" in msg_body
    print(f"\n[Test Success] SQS Received Message Content: {msg_body}")

    4. 💡 실무 적용 시니어 팁 (Practical Tips)#

    시니어 데이터 및 백엔드 엔드니어 입장에서 실무 도입 시 반드시 챙겨야 할 주의사항과 개선 방안을 공유합니다.

    • 동적 포트 바인딩 방식을 적극 채택하라:
      LocalStack 기본 포트인 4566을 호스트에 고정해 매핑(-p 4566:4566)하여 사용하면, 병렬로 실행되는 CI/CD 잡(Job)이나 로컬의 여러 프로젝트 빌드 환경에서 포트 충돌이 유발됩니다. Testcontainers가 보장해 주는 무작위 동적 할당 포트 조회를 사용하여 클라이언트를 초기화해야 멱등성 있는 병렬 테스트가 완성됩니다.

    • CI/CD 파이프라인(GitHub Actions, GitLab CI) 내 Docker Socket 허용:
      CI 러너가 Docker 내에서 테스트 컨테이너를 한 번 더 띄워야 하는 ‘Docker-in-Docker(DinD)’ 형태가 될 수 있습니다. GitHub Actions의 경우 다음과 같이 볼륨 마운트 혹은 디바이스 노출 설정을 포함해야 Testcontainers가 작동할 수 있습니다.

      # GitHub Actions 환경 예시
- name: Run Pytest with Testcontainers
  run: |
    pytest -v
  env:
    # Docker Daemon 통신 허용 설정
    DOCKER_HOST: unix:///var/run/docker.sock

    • LocalStack Community와 Pro 버전 차이를 인지하라:
      S3, SQS, DynamoDB, SNS, Lambda 등의 코어 서비스는 커뮤니티 오픈소스 에디션에서 완벽히 구동됩니다. 다만 AWS Cognito, Glue, RDS(실제 DB 엔진 인스턴스) 등 엔터프라이즈 기능은 LocalStack Pro 구독 라이선스가 필요할 수 있습니다. 필요한 경우 로컬 컨테이너 구동 방식을 분기하여 구성하십시오.

    5. 결론: 개발자 경험(DX)과 배포 안정성의 동시 혁신#

    통합 테스트의 가장 큰 적은 **‘플래키 테스트(Flaky Test, 성공과 실패를 종잡을 수 없는 테스트)’**와 **‘테스트 환경 구성의 피로도’**입니다.

    오늘 다룬 LocalStack과 Testcontainers의 조합은 개발자의 물리적인 개입(예: docker-compose 켜기, 인프라 생성 스크립트 수동 실행) 없이 코드 실행 한 번으로 완전무결한 Sandbox 클라우드 세계를 프로비저닝해 줍니다.

    AWS 요금 고지서의 부담을 **‘0원’**으로 수렴하게 만들고, 개발자 개인 PC와 CI 서버 모두 동일한 멱등적 테스트 생태계를 갖춰 보십시오. 실무 코드에 바로 이 전략을 이식하여 무결점 백엔드 딜리버리를 실현하시기 바랍니다.
